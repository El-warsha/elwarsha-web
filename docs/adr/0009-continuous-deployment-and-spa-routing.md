# ADR 0009 — Continuous deployment and SPA fallback routing on edge hosting

## Decision

Host `elwarsha-web` on edge-based static infrastructure (Vercel / Cloudflare Pages) using a dedicated routing configuration:

1. **Routing Strategy in `vercel.json`**:
   - Configure a single catch-all rewrite rule:
     ```json
     {
       "$schema": "https://openapi.vercel.sh/vercel.json",
       "rewrites": [
         {
           "source": "/(.*)",
           "destination": "/index.html"
         }
       ]
     }
     ```
   - Physical static files generated by the SSG pre-render step (`dist/ar/index.html`, `dist/en/index.html`, `dist/ar/initiative/index.html`, etc.) take precedence and are served directly by the CDN edge.
   - Any dynamic client-side routes (such as `/:locale/portal/*`, `/:locale/portal/cohorts/:slug/weeks/:num`) that do not exist as physical files on disk cleanly fall back to `dist/index.html`, where React Router handles route rendering.

2. **Prohibition of `cleanUrls` and `trailingSlash` Overrides**:
   - Do not enable `"cleanUrls": true` or `"trailingSlash": true` in `vercel.json`.
   - Vercel's clean URL rewriting conflicts with the fallback destination `/index.html`, creating redirect loops or unexpected 404 errors on deep dynamic links.

3. **Continuous Delivery**:
   - Deployment triggers automatically upon Git push to the production branch.
   - Pull Requests generate isolated preview deployments with distinct URLs, enabling team verification prior to merging.

## Why

1. **Zero Cold-Starts and Free CDN Edge Performance**: Static edge hosting provides sub-100ms response times globally for marketing and educational pages without server maintenance costs.
2. **Eliminates 404s on Refresh**: In an SPA with pre-rendered pages, direct navigation or hard page refreshes on non-prerendered portal subpages produce 404 errors unless the edge router explicitly rewrites unmatched paths to the SPA shell.
3. **Clean Contract with API**: Build-time environment variable `VITE_API_BASE_URL` points the client to the live API origin.

## Notes

- If custom domain routing is configured, `WEB_ORIGIN` on the backend API must be updated to match the custom domain to satisfy CORS requirements.
